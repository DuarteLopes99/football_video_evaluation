# Changes 2026-10-30 — Canedo 1080p run "detects nothing"

Run analysed: `💛💙 Canedo Fc - UD Mansores 1810 Jornada 2 💛💙_1080p.mp4` with
`configs/match_setup_Canedo_Fc_-_UD_Mansores_1810_Jornada_2__1080p.json`.
Test clip: `data/videos/canedo_seg_4980.mp4` (video 1:23:00–1:27:00, 2nd half) with
`configs/match_setup_canedo_seg_4980.json` (the same setup, times shifted by `scripts/make_segment_setup.py`).

## 1 · What was wrong

| What you saw | Root cause |
|---|---|
| Your manual input was not used: legend "Team A / Team B / GK TEA", grey boxes, no calibration | The run started **without `--setup`**. The launcher restored an empty "setup" choice remembered for this video (`p.setup ?? v.setup` keeps `''`), so `run_analysis.py` never saw the setup. |
| Frame 2:03:31 analysed (after the final whistle at 2:02:27) | Same cause (no periods), plus a 20-s margin around every period, plus no period filter in the analytics. |
| Report with **zero** everywhere | Even with the setup: calibration mode `ptz` with 21 clicked landmarks but **no solved camera file** → no homography → every pitch coordinate NaN → no possession, events, xG or distances. The PTZ tracker also refused any video that was not 640 × 360. The report said "Camera calibration usable on 100 %" (default when there is no camera log). |
| Fans, coaches, security boxed as players | The person detector fires on everybody; the old "outside" rule needed pitch coordinates (none) and was applied only at the end. |
| Grey (uncoloured) output | No setup → no kit classifier → every label "unknown". |

## 2 · What changed (by file)

| File | Change |
|---|---|
| `run_analysis.py` | Finds the setup of the video by file name when `--setup` is missing (`--no-setup` to skip); solves the camera from your landmark clicks before processing (`autocalib.ensure_calibration`). |
| `football_eval/match_setup.py` | `find_setup()`; checklist says the camera will be solved from the clicks. |
| `football_eval/ui/launcher.html` | An empty remembered setup choice no longer hides the setup; the setup file name is built like the Python side (emoji / leading `_`). |
| `football_eval/autocalib.py` **(new)** | Camera from the setup's landmark frames: closed-form camera per frame + RANSAC (mislabelled clicks dropped and printed), joint refinement, and comparison with every venue camera in `configs/` — the one that explains your clicks best is kept, with your landmark frames as anchors. Written to `configs/camera_<match>_ptz.json` and recorded in the setup (done once, ~15 s). Fallback: flow homography from the landmark frames. |
| `football_eval/ptz.py` | `camera_from_homography`, `solve_from_landmarks`, `initial_fit` (moved from the script); `PTZProvider` works at **any resolution** (1080p frames are tracked at 640 px and the homography is scaled back); first frame initialised from the best of all anchors + a global search; **every landmark frame is a checkpoint** (the tracker restarts from your pose when it passes it). |
| `football_eval/pitch.py` | Passes all anchors to the PTZ tracker. |
| `football_eval/people.py` **(new)** | Person types: `player`, `goalkeeper`, `referee`, *unknown* (on pitch, no kit) vs **`staff`** (touchline: coaches, bench, ball boys), **`steward`** (hi-vis vest: security), **`spectator`** (stands: fans). Zone from pitch coordinates, or from the grass mask when there is no calibration. Per-track majority. `people_summary()`. |
| `football_eval/perception.py` | Per detection: zone + type (`tracks.csv` columns `zone`, `ptype`); kit votes only for people on the pitch; off-pitch tracks get their type and no team; detector skips sky / terraces with the grass mask when there is no calibration; kit samples use the descriptor stored by the setup UI (no seek per click; clicks outside a cut clip still count); `meta.json` → `people`, `calibration` (usable share, first-frame init, anchors passed). |
| `football_eval/teams.py` | Clicked outfield samples that the other clicks put in the **other team** are ignored and reported (two "UD Mansores" clicks were shaded grass and pulled shaded yellow Canedo shirts to Mansores). |
| `football_eval/config.py` | `video.period_margin_s` 20 → **0** (game only); new `pitch.staff_band_m` (9 m), `pitch.hivis_min_share` (0.30). |
| `football_eval/analytics.py` | Analytics restricted to the periods (`restrict_to_periods`), also for re-runs from older tracks; writes `people_summary.csv`; report gets the detection section. |
| `football_eval/report.py` | New **"Who was detected"** section: detections per type and team, share of frames with pitch positions (says plainly when there is no calibration) and 4 coloured frames. |
| `football_eval/confidence.py` | Camera coverage without a camera log = share of frames with positions (was a fake 100 %). |
| `football_eval/live.py` | Colours + tags for `STAFF` (teal), `SEC` (yellow), `FAN` (mauve); full team names in the legend ("GK UD Mansores", not "GK TEA"); minimap shows only people playing; shared `annotate_frame()` used by the report and the debug video. |
| `scripts/render_debug_video.py` | Same colours / legend / team names as the live view, configuration taken from the run's `meta.json`. |
| `football_eval/review.py`, `football_eval/ui/app.html` | Review overlays draw staff / security / fans in their colours. |
| `scripts/make_segment_setup.py` **(new)** | Re-use a full-match setup on a cut clip. |
| `tests/test_pipeline.py` | 3 new tests (camera from clicks incl. a swapped label, 1080p ↔ 640 PTZ scaling, people types / periods / setup discovery / stored kit descriptors); windows test updated for margin 0. 25 / 25 pass. |
| docs | `STATS_RULEBOOK.md` §1 + new §1b (people types, game only), `USER_GUIDE.md` (setup always used, automatic calibration, colours, troubleshooting), `README.md` (new modules, v0.3 table). |
